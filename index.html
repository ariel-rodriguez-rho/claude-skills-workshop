5 skills in 50 minutes

A hands-on Claude Skills workshop — no coding. Learn the loop once, then build five skills you'll actually use, each with a live demo.

What's a skill? Every time you ask Claude for help, you re-explain the same things — your format, your tone, your checklist. A Skill is that explanation, saved: a small instruction file Claude automatically pulls up whenever it's relevant, in any chat, forever. Explain it once, and it's just how Claude works from then on.

SetupBefore we start (5 min)

  • Sign in at claude.ai (or the Claude desktop app)
  • In Settings → Capabilities, turn on “Code execution and file creation” — Skills need it
  • Find the Skills section in Settings — that's where uploads and on/off toggles live

The loopEvery skill is built the same 3 ways

Create — paste a “build me this skill” prompt into Claude. It interviews you, writes the skill, and hands back a zip file.

Install — go to Settings → Skills → Upload skill and upload the zip.

Test — open a fresh chat and run the demo prompt. Don't mention the skill: Claude should pick it up on its own. That's the magic moment.

Not quite right? Go back to the chat that built it, say what to change, re-upload. That edit loop is skill development. Now — five times through the loop, one useful skill each.

Skill 1 · warm-upweekly-status

Turns messy notes into your team's status update. The simplest possible skill — pure formatting — which is why it's first.

Create it

Help me create a custom skill called "weekly-status".

When I share raw notes about my week, format them as a status
update with these sections:
- WINS (done this week)
- IN FLIGHT (with expected dates)
- BLOCKED (each item names who can unblock it)
- NEXT WEEK

Tone: brief and direct, no corporate filler. Never invent dates.
Interview me if you need anything else, then package the skill
as a zip I can download.

Demo it (fresh chat, after installing)

Status update from these notes:

finished the vendor onboarding doc, legal signed off tuesday.
still chasing finance for the Q3 budget numbers, need them
before I can book the offsite venue. started interviews for
the coordinator role, 2 done 3 scheduled. next week: offsite
logistics, close out the audit checklist.

Notice: you never mentioned the skill — the request matched its description, so Claude used it automatically. BLOCKED names finance, because the skill says it must.

Skill 2meeting-notes

Raw transcript or scribbles in → decisions, action items, and owners out. The skill encodes what your team considers “captured.”

Create it

Help me create a custom skill called "meeting-notes".

When I paste meeting notes or a transcript, produce:
1. DECISIONS — what was decided, one line each
2. ACTIONS — a table: action, owner, due date
3. OPEN QUESTIONS — anything left unresolved

Rules: every action MUST have an owner — if the notes don't
name one, list it under OPEN QUESTIONS instead. Never pad;
if a section is empty, say "none."
Package it as a zip I can download.

Demo it

Clean up these meeting notes:

talked about the office move. sam says the lease is confirmed
for nov 1. we agreed to go with the phased move, ops floor
first. someone needs to get quotes from 3 moving companies by
friday. maria will own the comms plan to staff. also discussed
parking but no conclusion. jt asked about budget, sam to check
with finance and report back next week.

Notice: the moving-company quotes have no owner in the notes — so they land in OPEN QUESTIONS, not silently assigned. Your rule, enforced every time.

Skill 3email-triage

Your rules for what's urgent and what a morning briefing looks like. Paste emails in (or wire up the Gmail connector later — the skill works either way).

Create it

Help me create a custom skill called "email-triage".

When I share emails or ask for an inbox briefing, sort
everything into:
1. NEEDS ME TODAY — with a one-line summary and a suggested
   one-sentence reply each
2. WAITING ON OTHERS — who owes me what
3. FYI ONLY — one line each
4. SAFE TO IGNORE — just count them

Anything from my manager or containing "urgent", "deadline",
or "approval needed" goes to the top of NEEDS ME TODAY.
Interview me about my VIPs and common email types, then
package it as a zip I can download.

Demo it

Triage these:

1) From: facilities — "Reminder: fire drill Thursday 10am"
2) From: my manager — "Need your approval on the new vendor
   contract by EOD tomorrow"
3) From: newsletter — "5 trends in workplace ops"
4) From: recruiter-spam — "Exciting opportunity!!"
5) From: finance — "Sent you the Q3 numbers you asked for,
   let me know if anything looks off"

Notice: the manager's approval request jumps to the top with a drafted reply; the newsletter is one FYI line; the spam is just a count. Your priorities, applied without you restating them.

Skill 4vendor-compare

The checklist you always score vendors against — so any quotes you paste get judged the same way, every time. Skills can carry criteria, not just formats.

Create it

Help me create a custom skill called "vendor-compare".

When I share vendor quotes or proposals, compare them in a
table scored on: total first-year cost (including one-time
fees), contract length and exit terms, support level, and
implementation time. Then give a recommendation with the
single biggest risk of each option.

Rule: always surface hidden costs (setup fees, per-seat
overages, auto-renewal clauses) in their own row.
Package it as a zip I can download.

Demo it

Compare these two:

Vendor A: $500/month, 12-month contract, auto-renews, $2,000
one-time setup, email support, live in 2 weeks.

Vendor B: $650/month, month-to-month, no setup fee, phone +
email support, live in 6 weeks.

Notice: the auto-renewal clause and setup fee get their own row — the trap you built the checklist to catch, caught by default.

Skill 5brand-voice

How your team writes — tone, banned phrases, sign-offs. This one changes every writing task, which makes it the best team skill to share.

Create it

Help me create a custom skill called "brand-voice".

Whenever I draft or rewrite emails, announcements, or docs,
write in our voice: warm but direct, short sentences, active
voice, contractions are fine. Never use "circle back",
"leverage", "synergy", "per my last email", or exclamation
marks in professional messages. Lead with the point, details
after. Sign off with just my first name.

Interview me for a couple of writing samples to learn from,
then package it as a zip I can download.

Demo it

Rewrite this email:

"Per my last email, I wanted to circle back and leverage this
opportunity to touch base regarding the office move!!! It would
be greatly appreciated if all stakeholders could endeavor to
complete the relocation survey at their earliest convenience!"

Notice: every banned phrase is gone and the ask now leads. From here on, all your drafting in Claude sounds like you.

What's actually inside a skill zip?

One folder with a SKILL.md file — plain text with a tiny header. That's a complete skill:

---
name: weekly-status
description: Formats raw weekly notes into the team's
  status update. Use whenever the user shares weekly
  notes or asks for a status update.
---

Turn the user's notes into this exact format:
## WINS · ## IN FLIGHT · ## BLOCKED · ## NEXT WEEK
Brief and direct. Every BLOCKED item names who can
unblock it. Never invent dates.

The description is the trigger — Claude reads it to decide when the skill applies. Bigger skills can bundle templates and reference docs in the same folder, but plenty of great ones are just this.

SharingOne person builds it, everyone has it

The zip is the skill — send it to a teammate and they upload it in their own Settings. On Team and Enterprise plans, admins can publish skills to the whole workspace so everyone gets them automatically.

That's the multiplier: whoever best knows how a task should be done encodes it once, and the whole team's Claude gets better at it.

⚠️ Only install skills from people you trust. Skills can include runnable code — treat a skill zip like a macro-enabled file. Team-made and Anthropic-made: fine. Random internet downloads: read first.

Good to knowCommon questions

Do I need to know how to code?
No. You describe the skill in plain English and Claude writes the file.
How is this different from a Project?
A Project is a place — one workspace with its own docs and chats. A Skill is a portable how-to that follows you into every chat and activates itself when relevant. They combine well.
My skill didn't trigger.
Its description probably doesn't match how you phrased the request. Ask Claude to broaden the description and re-upload — or invoke it by name: “use my weekly-status skill.”
Can I turn one off?
Yes — every skill has a toggle in Settings. Off means Claude never sees it.
Which skill should I build first for real?
The task you've explained to Claude (or a new hire) more than twice. That repetition is the tell.
